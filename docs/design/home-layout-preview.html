The feed from the quick filters down, drawn at phone width with Roha sample content. Numbered markers show the four changes; the list beside the phone says where each one is made in the code. Daily essentials works: pick a tab, press ADD.

What changes

    Page order below the filters

    Why Daily essentials sits second

    • The first screen is already full, so it peeks in at the fold instead of fighting the header.
    • Categories come first because they are the door for a shopper who wants to browse.
    • It stays above Shop for your need: needs open a page, essentials add right here, so it is the faster path.

    How Daily essentials differs from the other rows

    • Shop for your need opens a page of items. Daily essentials adds to the cart in place.
    • Small prices is a price filter. Essentials is what this town buys every day.
    • Order again stays parked (owner, 2026-10-10). A "Your usual" tab is a follow-up once order history is mocked.

    Also touched by these changes

    • The item list is town data (a table with town_id), not code, so each town sets its own.
    • Loading skeleton must mirror the new order (ADR 0035): home/HomeSkeleton.tsx.
    • Words in en, hi and mr: the title and three tab names (a native speaker should check them).
    • Maestro home flow, section-order tests, an ADR and the Phase 1 report.

    Left out on purpose

    • Offers strip: coupons already have a banner; add only if the people test asks.
    • Product photos and the card-shape decision: separate passes.
    • Popular in Roha rail: needs order data, so Phase 2.
    • Subscriptions (daily milk): V2.
    • Shorter delivery line: dropped. The header already says "Delivering in 15–20 mins" or "Arriving today, 8–9 AM"; the long sentence I mocked is not in the header.
    Correction kept from last round. "Featured this week" is three collection cards (Monthly ration, Tiffin and lunchbox, Morning chai), not a product rail, so it keeps its name and place here.
