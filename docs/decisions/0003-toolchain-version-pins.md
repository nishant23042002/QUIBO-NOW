# 0003. Toolchain version pins

- **Status:** Accepted (Phase 0)
- **Date:** 2026-10-08

## Context

Versions were looked up in the npm registry on 2026-10-08. Several current releases are brand-new majors,
and some of the latest versions cannot be used together. Every version is an exact pin (`.npmrc` has
`save-exact`), shared versions live in the `catalog:` of `pnpm-workspace.yaml`, and the lockfile is
committed. Anything below `latest` is listed here with the reason and the condition to revisit it.

## Decision

| Tool                | Pinned to                   | Latest seen | Why not latest, and when to revisit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ------------------- | --------------------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Node                | 24.21.0 (`.nvmrc`, engines) | 26.11.0     | 24 is the LTS. The previous local Node, 22.12.0, is below the minimum of lint-staged 17 (22.22.1), Lighthouse 13 (22.19) and ESLint 10 (22.13). `engine-strict=true` makes a wrong Node fail loudly at install. Revisit when 26 becomes LTS.                                                                                                                                                                                                                                                                                                                                                                       |
| TypeScript          | 6.0.3                       | 7.0.2       | `typescript-eslint` 8.71.1 declares `typescript <6.1.0`, so TypeScript 7 would break type-aware linting. Revisit when typescript-eslint supports 7.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ESLint              | 10.12.0                     | 10.12.0     | The first plan was ESLint 9.39.5 because `eslint-plugin-react`, `-import` and `-jsx-a11y` (bundled by `eslint-config-next`) list ESLint 9 as their peer limit. That was **changed during Phase 0**: ESLint 9 reached end of life on 2026-08-06 (the registry marks 9.39.4 and 9.39.5, the two latest 9.x releases, as deprecated "no longer supported"), and those plugins' rules were checked to run correctly on ESLint 10. The three peer ranges are allowed explicitly in `pnpm-workspace.yaml` (`peerDependencyRules`), scoped to those plugins only. Remove the allowance when they publish ESLint 10 peers. |
| pnpm                | 10.34.5                     | 12.10.1     | Not stacked on top of this many new majors. Revisit as its own change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Vitest, MSW         | 5.0.3, 3.0.2                | same        | Current. Vitest lists `msw ^2` as an optional peer of its module mocker (used only for `vi.mock` in browser mode); allowed in `peerDependencyRules` because `packages/mocks` runs in Node mode.                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Tailwind CSS        | 4.3.3                       | same        | v4 has no JavaScript presets, so the "Tailwind preset" is `packages/ui/src/styles/theme.css` (an `@theme` block). v3 was rejected for a new codebase.                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Next.js, React, Zod | 16.4.0, 19.3.0, 4.6.5       | same        | Current. Next 16 renamed `middleware.ts` to `proxy.ts` and no longer prints "First Load JS" in `next build`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

**Install scripts.** pnpm 10 skips dependency install scripts. `unrs-resolver`, `esbuild`,
`@parcel/watcher` and `@swc/core` are listed in `ignoredBuiltDependencies` because each ships its binary
as an optional platform package and the project was run (lint, tests, builds, dev server) without their
scripts. Nothing is allowed to run a build script.

## Consequences

- Upgrading any pinned tool is a deliberate change that updates this file.
- The `peerDependencyRules` entries (three ESLint plugins and the Vitest mocker's optional `msw` peer) are
  the only places where a package manager warning was acknowledged instead of satisfied. Any other peer
  problem still prints.
